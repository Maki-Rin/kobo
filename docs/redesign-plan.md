# サイト改修計画

更新: 2026-10-26 / 状態: 方針案

## 方針

- 今の白黒シンプル路線を保ちつつ、洗練より「楽しげ」に寄せる。
- 文言はスタッフ目線のくだけた口調。AIっぽい定型文（「創造力を形に」「革新的な」等）は使わない。
- 稼働状況をサイトに来る理由の中心に置く（トップのheroの下に常設）。

## デザインの参考

- 立命館 TRY FIELD（https://www.ritsumei.ac.jp/tryfield/）: 黒一色、太いゴシックと線だけの文字（TRY / FIELD）の対比、矢印のモチーフ。白黒でも遊びがある。
- printer.playful.ist: 稼働状況カードの情報量（状態バッジ、温度、進捗、snapshot、最終確認時刻）。

## デザインの方向（案）

- 色: 白黒が基本。色は稼働状況の状態表示だけに使う。
- 文字: 見出しは太い欧文と、線だけの文字（アウトライン）を組み合わせる。日本語本文は読みやすさ優先。
- 形: 太めの黒い枠線、角丸控えめ。ホバーで少しずれる影など、触って楽しい動き。
- モチーフ: 矢印「→」をリンクや区切りに使う。
- 写真: heroの施設写真は活かす。

## Markdown変換のリファクタリング

現状（`src/lib/articles.ts`、`src/components/CodeBlock.tsx` ほか）:

- remark-html でHTML文字列を作り、見出しIDを正規表現で後から差し込んでいる。
- h3 に `!important` 付きのインラインstyleを埋め込んでいる。
- 目次は本文とは別の正規表現で抽出しており、変換結果とずれる可能性がある。
- 画像キャプション・リンクカード・コードブロックを、描画後にDOMを探して `createRoot` で差し替えている。
- HTMLエスケープを手書きで戻している（`SafeImage.tsx`）。

置き換え案:

- unified のパイプライン（remark-parse → remark-gfm → remark-rehype → rehype-slug 等）に統一する。
- 目次は同じ構文木から作る。
- キャプション・リンクカード・コードブロックは構文木の段階でコンポーネントに対応付け、サーバー側でReact要素として描画する（`dangerouslySetInnerHTML` と描画後のDOM書き換えをなくす）。
- 見た目はCSS（Tailwind typography 等）で当て、インラインstyleをやめる。
- 既存記事のMarkdownはそのまま表示できることを確認しながら移行する。

## 進め方

1. Markdown変換のリファクタリング（記事ページの土台。デザイン変更の前に行う）
2. 共通の見た目（色・文字・余白の決まり、ヘッダー、フッター、ボタン）
3. トップページ（hero、稼働状況、How to Fab、Works、Events）
4. 記事一覧・記事ページ
5. 稼働状況ページ
6. 文言の全面見直し

各段階でスマホとPCの表示を確認する。push はレイアウト確定まで行わない。

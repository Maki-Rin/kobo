# コンテンツの区分けと投稿の仕組み（検討メモ）

更新: 2026-10-27 / 状態: 検討中

## いまの構成

| 区分 | 中身 | 置き場所 | 詳細ページ |
|---|---|---|---|
| How to Fab | 機材・ソフトの使い方の記事 | `src/content/articles/*.md` | `/articles/[id]` |
| Works | スタッフが選んだ作品（写真・説明・タグ） | `public/data/works.json` | なし（トップのカルーセルのみ） |
| Events | 告知画像と日付だけ | `public/data/events.json` | なし |

やりたいこと:

- 技術系の文章（使い方以外の知見・検証・トラブル対応）を載せる
- KOBOが開催・主催したイベントの記録を載せる
- 作品は今のままでよいが、将来は利用者からの投稿を受けたい
- それに合わせて投稿画面を変える

## 先行事例で見たこと

| サイト | 区分け | 参考になる点 |
|---|---|---|
| ProtoPedia（作品投稿） | 作品／イベント／開発素材。作品はカテゴリ（ハード・ソフト・デザイン・メイカー）とタグ | 作品ページの項目: 完成・開発中の状態、概要、関連リンク、画像・動画、使った素材やツール、システム構成、ストーリー（きっかけ・課題・できること・まだできていないこと）、メンバー、**関連イベント**、似た作品 |
| Hackster.io（作品投稿） | Projects／Channels／Contests／Events | 冒頭に**難易度・状態（制作中）・所要時間**、「使ったもの」、ストーリー、コード、クレジット |
| Instructables（作り方投稿） | Projects／Contests | 「材料」と「Step 1, 2, …」の決まった型。手順書として読みやすい |
| Printables（3Dモデル） | Models／Contests／Events／Education | 説明、**印刷設定**、タグ、元になったモデル（リミックス）、ライセンス。他人が「作ってみた」投稿を元の作品に結びつける仕組み |
| Zenn（技術記事） | 記事を **Tech と Ideas** の2種類に分け、トピック（タグ）で横断 | 種類は2つだけで、細かい分類はトピックに任せている |
| TRY FIELD（立命館） | NEWS／EVENTS／PROJECTS／STORY | お知らせ・イベント・プロジェクト・人の話を分けている。施設予約への導線が目立つ |
| ファブラボ鎌倉 | NEWS／PROGRAMS／FACILITY | 講座・オープンラボなど「参加の仕方」で分けている |

共通して言えること:

- **種類は少なく、横断はタグで**。種類を増やしすぎると、書く側が迷う。
- 作品とイベント、作品と作り方を**互いにリンク**している（関連イベント、元になったモデル、使ったもの）。
- 作品ページは「状態・難易度・所要時間・使ったもの」を冒頭に**決まった項目**で出す。本文は自由。
- 利用者の投稿は、どのサイトもアカウント制で、運営側の審査や通報の仕組みを持つ。

## 区分けの案

読む人の目的で3つに分け、機材をまたぐタグで横断する。

```
まなぶ（記事）
├─ ガイド      … 機材・ソフトの使い方。手順書（今の How to Fab）
└─ テック      … 設定の検証、トラブル対応、Tips、試してみた
みる（作品）
└─ 作品        … 写真中心。いまはスタッフ選、将来は利用者投稿
あつまる（イベント）
└─ イベント    … KOBOが開催・主催するもの。開催前は告知、開催後はそのページに記録を追記する
```

- 「ガイド」と「テック」は同じ「記事」の仕組みで、種類（`type`）だけ変える（Zenn の Tech／Ideas と同じ考え方）。
- 開催したイベントの記録は、記事として別に立てずに**そのイベントのページに追記**する。告知と記録が1つのURLにまとまり、「どんなイベントをやってきたか」が一覧で見える（過去の開催実績になる）。
- 記録が長くなる回や、複数人で書く回だけは、記事（テック等）として書いてイベントから結びつけてもよい。
- **機材タグ**（3Dプリンタ・レーザーカッター・刺繍ミシン など）を全種類で共通にする。機材ごとに「使い方・知見・作品・稼働状況」がつながる。将来は機材ごとのページ（`/machines/adventurer-5m-pro` など）をまとめ役にできる。

## 各種類の項目

| 項目 | ガイド | テック | イベント（告知） | イベント（開催記録） | 作品 |
|---|---|---|---|---|---|
| タイトル・カバー画像・本文 | ○ | ○ | ○（本文は任意） | ○（記録の本文） | ○ |
| 書いた人（複数可） | ○ | ○ | － | ○（記録を書いた人） | ○（作った人） |
| 機材タグ・トピックタグ | ○ | ○ | ○ | ○ | ○ |
| 難易度・所要時間 | ○ | － | － | － | ○ |
| 使ったもの（材料・ソフト・設定） | ○ | 任意 | － | － | ○ |
| 最終確認日（情報の鮮度） | ○ | ○ | － | － | － |
| 日時・場所・定員・申込リンク・状態（予定／終了） | － | － | ○ | （終了） | － |
| 参加人数・主催／共催・担当スタッフ | － | － | － | ○ | － |
| 写真ギャラリー（複数） | － | － | － | ○ | ○ |
| 参加者の作品 | － | － | － | 任意（作品へのリンク） | 任意（関連イベント） |
| 状態（完成／制作中） | － | － | － | － | ○ |
| 元にしたガイド・データ配布リンク・ライセンス | － | － | － | － | 任意 |

イベントは本文より決まった項目（日時など）が中心なので、投稿画面ではMarkdown欄より入力フォームを主にする。

## サイトの構成（レイアウト）

```
トップ
├─ hero
├─ 稼働状況（いまのまま）
├─ 次のイベント（予定があれば1〜2件。なければ非表示）
├─ 新着（ガイド・テック・開催したイベントの記録を混ぜて、種類のラベル付き）
├─ 作品（ピックアップ）
└─ はじめての人へ（ガイドの入口）

ヘッダー: 稼働状況／まなぶ／作品／イベント／KOBOについて
```

| ページ | URL | 中身 |
|---|---|---|
| まなぶ（一覧） | `/articles` | ガイド／テックの切り替え、機材タグで絞り込み。既存URLは維持 |
| 記事 | `/articles/[id]` | 種類のラベル、機材タグ、難易度など。関連記事・関連作品 |
| 作品（一覧） | `/works` | 写真のグリッド、機材タグで絞り込み |
| 作品 | `/works/[id]` | ギャラリー、状態・難易度・所要時間・使ったもの、本文、関連イベント・元にしたガイド |
| イベント（一覧） | `/events` | 予定と開催済みを分けて表示。開催済みは写真と記録の有無がわかるカード |
| イベント | `/events/[id]` | 開催前: 日時・場所・申込・告知画像・内容。開催後: 上に「開催記録」（写真、やったこと、参加人数、参加者の作品）を追加し、告知部分は下にたたむ |

同じイベントを毎年・毎月やる場合（シリーズ）は、`series` で束ねて回ごとの記録を並べられるようにする。

## データの置き場所

いまと同じく Git 上のファイルを正本にする。

```
src/content/articles/*.md   … ガイド・テック（front matter の type で区別）
src/content/works/*.md      … 作品（works.json から移す）
src/content/events/*.md     … イベント（events.json から移す）。告知と開催記録を1ファイルに持つ（記録は `report:` 以降の本文など）
public/images/{articles,works,events}/<id>/…
```

- 既存の記事には `type: guide` を足す（既定値にすれば書き換えなしでもよい）。
- タグは `machines: [adventurer-5m-pro]`、`topics: [...]` の2種類。機材の一覧は1か所（`src/content/machines.json` など）で管理し、稼働状況のプリンタとも対応づける。

## 利用者からの作品投稿（将来）

段階を分ける。

1. **スタッフが代わりに登録**: 作品の投稿画面を作り、スタッフが写真と話を聞いて載せる。仕組みは今の投稿画面の延長。
2. **利用者が投稿し、スタッフが審査して公開**: 利用者用の投稿フォーム。公開前に必ずまとめ役が確認する（「審査待ち → 公開／差し戻し」）。
3. （必要なら）利用者のプロフィールページ、「作ってみた」の結びつけ、いいね など。

2に進むときに決めること:

- 誰が投稿できるか（学内の人だけか、誰でもか）とログイン方法（パスキー、大学のGoogleアカウントなど）
- 審査する人と、差し戻し・削除依頼の流れ
- 写真の扱い（人の顔、学外の人、著作物）と同意の取り方
- 画像の量が増えるので、置き場所をGitからオブジェクトストレージ（Cloudflare R2など）に移すか
- 迷惑投稿の対策（件数制限、サイズ制限、審査前は非公開）

## 投稿画面の変更

- 「新しく書く」で種類を選ぶ（ガイド／テック／イベント／作品）。種類ごとに設定パネルの項目と、本文のひな形を変える。
  - ガイド: 「準備するもの」「手順」の見出し入りのひな形
  - イベント: 日時・場所・申込をフォームで入力。本文は任意。開催日を過ぎると編集画面に「開催記録を書く」欄が出る（写真をまとめて追加、参加人数、「やったこと」「参加者の声」「次回に向けて」のひな形）
  - イベント一覧で、開催済みなのに記録がないものを目立たせる（書き忘れ防止）
  - 作品: 写真を複数並べるギャラリー欄、状態・難易度・使ったもの
- 一覧は種類で切り替え、機材タグで絞り込み。
- 段階2では「審査待ち」の一覧と、承認・差し戻しの操作を足す。

## 決めたいこと

1. 区分けと名前: 「まなぶ／作品／イベント」「ガイド／テック」でよいか
2. ガイドとテックを同じ一覧にまとめるか、メニューから分けるか
3. 作品の利用者投稿をいつ頃から始めたいか（段階1だけ先にやるか）
4. 利用者投稿の対象（学内のみか）とログイン方法
5. 優先順位（例: 種類と機材タグ → イベント（告知と開催記録） → 作品ページ → 利用者投稿）
6. 開催記録を公開する際の写真の扱い（参加者の顔の写り込み、事前の告知と同意）
